# 计划：build.mjs 主要函数单元测试

## 背景

`scripts/build.mjs` 的内部函数（`parseArgs` / `peerExternals` / `thirdPartyFromMetafile` / 三道门禁）目前未导出、无单测；`tests/dist.test.mjs` 只通过 `buildBundle` 做端到端**正向**验证——门禁在"合法产物"路径上不误报是被证明的，但**失败路径**（违规 import、清单不一致、超预算、未知 CLI 参数）完全没有覆盖。本计划为这些纯函数补单元测试，用手工 fixture 验证判定逻辑，不 mock esbuild。

## 铁律 5 对照

本次不改 `BUDGET` / `INLINED_THIRD_PARTY` / esbuild 版本的**取值**，只调整导出面（常量照常导出、门禁参数化默认值不变、产物零字节漂移）。属文档先行范围，以本文件记录。

## 改动

### 1. `scripts/build.mjs` 最小可测化（行为不变）

- 导出：`BUDGET`、`ALLOWED_IMPORT_PREFIXES`、`INLINED_THIRD_PARTY`、`parseArgs`、`thirdPartyFromMetafile`、`gateImportWhitelist`、`gateInlinedThirdParty`、`gateVolume`
- `peerExternals(pkg = PKG)` — 参数化以便注入 fixture pkg
- `gateInlinedThirdParty(metafile, declaredList = INLINED_THIRD_PARTY)` — declared 参数化
- `gateVolume(outBytes, budget = BUDGET)` — budget 参数化（gzip 超限分支无需构造 >12 KB 文件）
- 拆出 `collectImportSpecifiers(src) → Set<string>`（非相对说明符集合），`gateImportWhitelist` 内部调用它；错误消息文案不变

### 2. 新增 `tests/build.test.mjs`（风格对齐 dist.test.mjs：node:assert/strict + check() 计数器，无新依赖）

1. **parseArgs**：默认值 `{minify:true, report:false, outfile:"./dist/index.js"}`；`--no-minify`/`--report` 单独与组合；`--outfile p` 取值；未知参数 throw `/未知参数/`
2. **peerExternals**：注入 pkg 返回 keys；无 peerDependencies → `[]`；真实 PKG 结果与 package.json 一致（防漂移）
3. **thirdPartyFromMetafile**：非scoped/scoped 包名提取、同包去重、非 node_modules 与空 inputs → 空集合
4. **collectImportSpecifiers**：静态/裸/动态 import、`export * from`、`export {x} from` 均提取；相对/绝对路径不返回；`important`/`exported` 等伪关键字不误报
5. **gateImportWhitelist**：白名单内 Buffer 通过；裸包/scoped 非白名单/动态违规 import → throw `/未授权的 import/`
6. **gateInlinedThirdParty**：一致通过；"实际打进但未登记"、"已登记但未打进"、双向不一致三种 throw 消息
7. **gateVolume**：返回 `{raw,gz}` 且与实测一致；超 raw 预算 throw；注入小 budget 验证 gzip 超限分支 throw
8. **一致性回归**：对已提交 `dist/index.js` 跑 `collectImportSpecifiers`，结果全部落在 `ALLOWED_IMPORT_PREFIXES` 内（防重构后与 dist.test.mjs §8 判定漂移）

### 3. `package.json`

`scripts.test` 追加 `node tests/build.test.mjs`

### 4. `AGENTS.md`

Structure 表加 `tests/build.test.mjs`；Commands 的 `npm test` 说明改为三个测试串行
